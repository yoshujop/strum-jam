# Audit: charting

## Verdict
"Play any of your favourite songs" does not work as a product promise. Every path starts with a live iTunes search, so with no network (or Apple throttling) nothing outside the 17 built-in public-domain songs can even be found. From this sandbox ALL music hosts are blocked (itunes.apple.com, datasets-server.huggingface.co, labs.api.listenbrainz.org, open.spotify.com, lrclib.net, musicbrainz.org: ERR_TUNNEL_CONNECTION_FAILED), so my measurements are (a) the real embedded offline data in the built page and (b) the real pipeline with mocked network; the real Chordonomicon rows, the 30 s preview check, the Claude web path and LRCLIB could not be exercised live. Measured on 90 well-known recordings: only 40 (44%) are in the embedded Chordonomicon index, 61 (68%) in the embedded Hooktheory table, 22 (24%) in neither (every 2022+ hit, Hey Soul Sister, Free Fallin', Seven Nation Army, Africa, Redemption Song, Wonderful Tonight) and those dead-end at "add your Anthropic API key". Hooktheory-only charts are fragments: median 47 s / 20 bars of the song, 18/61 are 30 s or less, sections are called "Part 1 (0:38)", 50/61 are rated Hard because chords are given at sounding pitch with no capo (Riptide = Bbm/Ab/C#, Wonderwall = F#m7/B7sus4), 13/61 have double-time or absurd tempos (House of the Rising Sun 246 bpm in 4/4, Hallelujah 206, Perfect 192 in 3/4), 27/61 have chords smeared across bar lines, and none has a strum pattern. The Chordonomicon path (mocked rows) has full sections but no timing data at all: without a usable preview every chord is one bar at a default 100 bpm, and when Hooktheory durations are merged at the wrong tempo the bars come out as garbage (Wonderwall: "Em7 . . G | . . Dsus4 ."). Strum pattern and drum groove are never produced for dataset or Hooktheory charts (the only code that asks for them is switched off). Vocals: lyrics are line-synced to recording time but the chart is not the recording's bar structure, so words and chords only line up by luck; with a Hooktheory-only chart 40 of 57 lyric lines fall off the end of the chart; the "real melody" needs the player to supply an audio file of the song, otherwise it is "sing any chord tone". Verified correctness bugs: a network failure is reported as "not in the chord dataset"; a hash false positive (0.5% per key) plus an unreachable Spotify oEmbed silently charts a different song; the confirm dialog claims it "compared with the recording's preview" when it did not.

## How it works
ALL PATHS (file:line in /home/user/strum-jam/src)

1. 2. Chart.make (26-chart.js:29-105):
 a. Lookup.findRows (25-lookup.js:343-378): normTitle x artistVariants -> FNV-1a hash -> embedded index (vendor/chord-index.bin, magic SJCI, 2^14 buckets, 12-bit check, 456,840 entries of 20-bit row number; measured load 33 ms, false-positive rate 0.5%). No hit -> ListenBrainz labs spotify-id-from-metadata + Spotify oEmbed titles to retry. Each candidate row (max 6, SEQUENTIAL) is fetched from datasets-server.huggingface.co/rows (20 s timeout x3) and its title verified via open.spotify.com/oembed. Row = Chordonomicon chord string with <verse_1> style tags, NO durations, NO tempo, NO key, NO capo (shapes as written on the tab site). parseCN 25-lookup.js:396-413.
 b. Lookup.findHT (25-lookup.js:284-299): embedded vendor/hooktheory.json.gz (15,065 songs, key "artist-slug|title-slug", each = 1-12 clips of [startSec, bpm, metre, key, nkeys, "Chord:beats ..."]; 57% of songs have ONE clip; median total 26 s of music per song; 830 songs use metres the game doesn't support (6/4, 5/4, 9/4) and are forced to 4/4 at 26-chart.js:182; melody data from the source dataset was dropped). Loads in ~220 ms.
 c. Source choice (26-chart.js:47-54): dataset rows; else Claude web (only if canWeb); else Hooktheory clips alone (htSections 26-chart.js:152-163, sections named "Part N (m:ss)"); else throw not_in_dataset.
 d. Preview check (26-chart.js:56-68, 47-analyze.js): fetch iTunes 30 s previewUrl, Basic Pitch over it, beat tracking -> bpm, beats, key, transposition offset, per-chord durations seen in those 30 s, fit ratio. If fit < 0.8 and canWeb -> web backup automatically (26-chart.js:74-83).
 e. Hooktheory second opinion: htMatch (25-lookup.js:302-320) finds the transposition; htCorrect (26-chart.js:109-150) overwrites chart chords with HT's.
 f. merge (26-chart.js:169-249): bpm = preview bpm, else web bpm, else HT bpm ONLY for HT-only charts (line 179-180), else 100. Chord lengths = median of durations observed in the preview / HT clips keyed by (prev|chord|next), snapped to 1,2,3,4,6,8,12,16 beats, else one bar. Claude timing prompt (timingPrompt 26-chart.js:421) is the only source of strum/drums for dataset charts and is disabled: ASK_TIMING=false (26-chart.js:27).
 g. build (26-chart.js:286-376): key via fitted Krumhansl-style scorer (25-lookup.js:416-467) + audio + HT + web votes; issues list (pitch/capo, chord swap, fit, low-confidence section) -> confirm modal; Lookup.layout (25-lookup.js:472-494) cuts beats into bars; style from genre regex (25-lookup.js:497-511).
 Output: title/artist/album/year/trackId/durationMs/previewUrl/art, bpm, time (4/4,3/4,2/4,6/8,12/8), feel, style, capo, tuning, key, sections[{name,bars[],conf}], strum (web only), drums (never), prov. validateSong clamps bpm 40-240, max 40 sections / 240 bars (20-songs.js:76-131). Difficulty = UI.difficulty (70-ui.js:122-133) from average shape difficulty/barre/bpm.

3. Claude paths (70-ui.js:77-80, 347-415): (i) player's own Anthropic API key, direct browser call to api.anthropic.com/v1/messages with web_search_20250305 max_uses 6, model default 'claude-sonnet-5', thinking disabled, up to 5 pause_turn rounds, prompt webChartPrompt (26-chart.js:436-452) demanding >=2 sources, sections in played order, per-chord beats, key/capo/bpm; (ii) claude.ai viewer window.claude 'sample' capability (70-ui.js:35, 354): no web search, so canWeb() is false in the artifact and a song missing from the data is a dead end there ('no_web'); (iii) shared worker SHARED_URL = '' (70-ui.js:5) i.e. OFF. api.anthropic.com is the only relevant host reachable from this sandbox (no key available, not exercised).

4. Fallback: paste a chord sheet (parseChordSheet 20-songs.js:305; verified: reads [Section] headers, capo line, x4 repeats, skips lyric lines; one chord = one bar, no tempo).

5. Caching: finished charts in localStorage 'charts' keyed it<trackId>, max 80 (26-chart.js:14-20); 'mine' list max 40 (70-ui.js:113-117); rowsMemo 60 in memory; lyrics per song key 'lyr:<trackId>' (61-lyrics.js:38-41). ## Problems

### [critical] Coverage: a quarter of famous songs dead-end at 'add your Anthropic API key'; anything recent is missing
- Where: src/25-lookup.js:343-378, 284-299; src/26-chart.js:47-54; src/70-ui.js:5, 77-80, 263
- Evidence: 90 well-known recordings, real embedded data (probe_local.js -> local.json): Chordonomicon index hit 40/90 (44%), Hooktheory 61/90 (68%), either 68/90 (76%), neither 22/90 (24%). Misses with no source at all: Hey Soul Sister, Free Fallin', As It Was, Espresso, Birds of a Feather, Beautiful Things, Too Sweet, Stick Season, Heat Waves, Dynamite, Lemon (both spellings), La Bamba, Bella ciao, Redemption Song, Wonderful Tonight, Seven Nation Army, Holocene, Motion Sickness, Africa, Fast Car (Luke Combs), 'Country Roads' (short title). No Chordonomicon index entry even for Creep, Zombie, Smells Like Teen Spirit, Someone Like You, Perfect, Shallow. Both datasets are frozen snapshots (about 2022-2023). The only remedy offered is a personal Anthropic API key (not available at all inside the claude.ai artifact; shared service SHARED_URL is empty).
- Fix: Stop depending on two frozen academic datasets plus a bring-your-own-key fallback. Stand up one server-side chart service (the worker the code already anticipates) that every client calls: it resolves the recording, returns a cached full chart if one exists, otherwise generates one (LLM + web sources + audio check) once and stores it for everyone. Ship a curated, hand-verified pack of the 300-500 most-requested beginner songs inside the build so the headline songs are instant, correct and offline.

### [critical] Hooktheory-only charts are fragments, not songs
- Where: src/26-chart.js:50-51, 152-163
- Evidence: pipeline_blocked.json (61 charts that resolved with the network blocked, all src=hooktheory): median chart length 47 s / 20 bars; 18/61 are 30 s or less, 44/61 are 60 s or less (Wagon Wheel 13 s, Blinding Lights 11 s, Viva la Vida 14 s, Sweet Home Alabama 6 bars/15 s, Hotel California 16 bars). Across the whole table: 57% of 15,065 songs have a single clip, median 26 s of music per song. Sections are named 'Part 1 (0:38)', 'Part 2 (1:22)': no verse/chorus, no intro/outro, no repeats. This is also what an online player gets whenever the song is in Hooktheory but not Chordonomicon and they have no API key.
- Fix: Never present clips as a song. Use Hooktheory only as evidence (key, tempo, chord durations, chord corrections) for a full-form chart; if only clips exist, label it honestly as a 'riff/loop drill' (loop the verse or chorus N times with a proper name) rather than a song run.

### [critical] No timing source for full charts: chord lengths and tempo are guessed, and get corrupted when merged
- Where: src/26-chart.js:173-181 (bpm), 208-226 (f = bpm / cl.bpm), 228-247 (fallbacks), 27 (ASK_TIMING=false)
- Evidence: Chordonomicon rows carry no durations/tempo. mock_cn.js (mocked HF row, no preview): Wagon Wheel and Tennessee Whiskey come out at bpm 100 'default', every chord exactly one 4/4 bar (timing.default 91/91 and 38/38); Tennessee Whiskey (really slow 6/8, 4:53) becomes 4/4 at 100 bpm lasting 91 s. Wonderwall with Hooktheory durations merged: bpm 100 default although Hooktheory says 174 (HT bpm is only used for HT-only charts), and HT's beat lengths are rescaled by 100/173 so bars read 'Em7 . . G | . . Dsus4 . | A7sus4 . . Em7 | . G . .' : chords drifting across bar lines for the whole song. Even with the preview, durations are only observed for chord contexts that occur inside those 30 s; everything else inherits a median. Not testable here: how well the real preview analysis fixes this (Apple previews unreachable).
- Fix: Make bar-level timing a first-class requirement of the chart format: every chart must come with beats-per-chord that sum to the recording length at its bpm, validated (total duration within about 5% of durationMs; chords start on beats 1 or 3 unless marked). Take bpm from Hooktheory when present, never rescale HT durations by an unrelated tempo, and reject/flag charts that fail validation instead of shipping them.

### [major] Tempo is frequently double-time or absurd
- Where: src/26-chart.js:179-185; src/20-songs.js:82
- Evidence: 13/61 offline charts are at or above 160 bpm; at least 9 are wrong in feel: House of the Rising Sun 246 bpm in 4/4 (slow 6/8 song; clamps to 240), Hallelujah 206 (Buckley) and 169 (Cohen) in 4/4 (slow 6/8), Perfect 192 in 3/4, Stairway 197, Good Riddance 192 (about 95), Creep 183 (about 92), Wonderwall 174 (about 87), The Night We Met 174 (about 87), Landslide 160 (about 80). The band and drummer then play a full-speed groove at twice the song's pulse. Other direction: Knockin' on Heaven's Door, Hotel California, Losing My Religion, Jolene, Dreams all land on exactly 100 (HT clip tempos that look like defaults).
- Fix: Normalise tempo to the felt pulse (60-140 window by halving/doubling together with chord lengths), detect compound metre (HT 3/4 at 190+ or 6/4 means 6/8 or 12/8), and store both tatum tempo and felt tempo. Add a per-chart sanity check: average chord length should be at least 2 felt beats for strumming songs.

### [major] No strum pattern and no drum groove on any dataset/Hooktheory chart
- Where: src/26-chart.js:27, 97-100, 356-360; src/25-lookup.js:497-511
- Evidence: strum is '' for 61/61 offline charts and for all mocked Chordonomicon charts; style was 'rock' for all 61 (genre regex fallback). strum/drums are only filled from Claude's timing answer (disabled by ASK_TIMING=false) or from a web chart. So a searched song plays as one chord card per bar with a generic band loop: the 'flashcard' feeling.
- Fix: Chart schema must include a strum pattern per section (D/U grid with accents, mutes) plus a groove id; derive it from metre + felt tempo + genre via a hand-authored pattern library (about 20 patterns), let the curated pack override per song, and make the gameplay judge strums against it.

### [major] Charts are at sounding pitch with no capo/easy-shape pass: famous beginner songs come out as barre-chord songs
- Where: src/26-chart.js:298-305, 339-349, 378-388; data spelling from vendor/hooktheory.json.gz
- Evidence: 50/61 offline charts rated Hard (diff 3), 7 Easy. Riptide = Bbm / Ab / C# (everyone plays Am G C capo 1), Wonderwall = F#m7 A Esus4 B7sus4 capo 0 (Em7 G Dsus4 A7sus4 capo 2), Jolene C#m E B, Landslide Eb Bb/D Cm7, I'm Yours B F# Abm E, Mr. Brightside C# F#maj7 Bbm. Capo is only ever proposed when a Chordonomicon chart disagrees with the recording (pitch issue); Hooktheory-only charts never get one (capo0 = web ? web.capo : 0). Enharmonic spelling is also wrong in sharp keys in 10/61 charts (E/Ab in A, Abm in B and E, Ebm7/F# in B, 'C#' chords under a 'Db' key label).
- Fix: After the sounding key is known, always run a capo solver: choose the capo 0-7 that minimises total shape difficulty (the chordDifficulty function already exists) and present 'Capo 1: Am G C' as the default with 'no capo' as an option. Respell chords from the key signature. Offer an explicit Easy arrangement (drop slash basses/extensions, cap chord changes to 1-2 per bar).

### [major] Network failure is reported as 'This song isn't in the chord dataset. Add your Anthropic API key'
- Where: src/25-lookup.js:369-377 (catch -> continue), 334-339; src/26-chart.js:36, 53; src/70-ui.js:263
- Evidence: flow.js case 2: Tennessee Whiskey IS in the index (1 row); with the Hugging Face host failing, Chart.make throws code not_in_dataset after 1.8 s and the UI shows the add-API-key copy. Same in pipeline_blocked.json for Wagon Wheel (Darius Rucker), Flowers, Fast Car (Tracy Chapman, 2 rows), Use Somebody (2 rows), Pink Moon, Besame Mucho. hfRow errors are swallowed per row and the pipeline cannot tell 'no row' from 'row unreachable'. The whole chart source hangs on an unversioned third-party dataset viewer API (row offsets; 'dataset row moved' guard).
- Fix: Track fetch failures separately (rowsTried/rowsFailed) and surface 'couldn't reach the chord database, retry' with a retry button. Longer term: host the chord data yourself (static shards on the game's own CDN keyed by hash) so there is one dependable origin.

### [major] Wrong song can be charted silently (hash false positive + unverified row)
- Where: src/25-lookup.js:245-251, 372-375
- Evidence: Index false-positive rate measured 0.515% per key (20,000 random keys; each lookup tries several title x artist variants). flow.js case 3: a nonsense title that collides in the index, with Spotify oEmbed unreachable, returns src 'dataset', issues 0, checked false, chords 'F Bb C F Bb C Dm Bb F C' from an unrelated row. The verification is skipped whenever oEmbed fails (st == null is accepted). With no preview there is no second check either.
- Fix: Store a wider check (or a tiny title fingerprint) in the index, and treat an unverifiable row as unverified: require either title verification or a preview fit before accepting; otherwise ask the player.

### [minor] Confirm dialog states a check that did not happen
- Where: src/26-chart.js:339-341; src/70-ui.js:284-287
- Evidence: flow.js: with no preview at all (audioErr 'No preview'), the modal reads 'The chords come from the Chordonomicon dataset. I compared them with the recording's preview and found this: ... Hooktheory's transcription of this recording is 2 frets higher'. prov.checked is set true by the Hooktheory pitch path. Screenshot: /tmp/claude-0/-home-user-strum-jam/bfa410c2-f824-5051-9a3c-70f51a4346d2/scratchpad/audit/charting/flow_confirm.png. The modal also exposes data-plumbing vocabulary (Chordonomicon, Hooktheory, dataset) to a beginner.
- Fix: Separate prov.checkedAudio from prov.checkedHT; in the redesign replace the questionnaire with one decision at most ('Play with capo 2 (easier) / no capo') and keep provenance in an info sheet.

### [major] Search is 100% dependent on Apple's US iTunes API; no offline or fuzzy search, slow multi-step flow
- Where: src/70-ui.js:171-198, 209-260, 1334-1349; src/25-lookup.js:47-62, 369-376
- Evidence: search_ux_blocked.js: with the network blocked, typing 'wonderwall oasis' gives 'Finding recordings...' then 'Couldn't reach the music databases' (screens search_fail_laptop.png / search_fail_phone.png in the scratch dir); the 15k-song Hooktheory table and 457k-entry index embedded in the page cannot be searched by title. Flow when online (mocked, flow.js): type -> suggestions about 2 s after first keystroke -> Enter -> list of recordings incl. live cuts and covers ('Wonderwall (Live)' ranked first as Apple returned it; rankRecordings is only used by Story mode) -> Pick -> 5-step panel -> confirm modal -> song screen -> choose mode: 5-6 interactions before playing. Timing with network blocked: median 2.4 s to an answer, worst 16.2 s (House of the Rising Sun, 7 candidate rows fetched one after another, each with retries). country=US hard-coded; misspelling/non-English tolerance is Apple's only (not testable here).
- Fix: Ship a searchable catalogue (title, artist, popularity, chart-ready flag) for the charts you actually have, with local fuzzy matching (trigram/edit distance) and instant results; use the online catalogue search only to extend it. Rank originals first everywhere (reuse rankRecordings), auto-pick the canonical recording, fetch candidate rows in parallel, and go straight to a ready-to-play song card.

### [critical] Vocals: lyrics and chords are on different clocks; most lyrics fall outside fragment charts
- Where: src/61-lyrics.js:32-37, 87-104; src/71-inst.js:54-56, 76-85
- Evidence: Lyric lines are in recording seconds; the chart is its own bar count at its own tempo, joined by a single offset T0 (fitMap). flow.js case 4, synthetic LRC for a 4:18 song (57 lines, 0:20-4:00): Hooktheory-only Wonderwall chart (65 s) -> 17/57 lines inside the chart, fit score -0.67, the other 40 lines land after the chart has ended; Chordonomicon-shaped chart (235 s at a default 100 bpm vs the record's 87) -> lines are 'inside' but the chord under each line is whatever bar the wrong tempo has reached (fit 0.04, i.e. no beat/bar agreement). Unsynced lyrics are spread evenly over 8%-90% of the duration (pure guess). The fix offered to the player is a +-bar nudge button. LRCLIB itself was unreachable here, so fetch hit-rate is not measured.
- Fix: A Vocals-capable chart must be time-aligned to the recording: store section/bar start times in recording seconds (from the generation service or from Hooktheory clip start times, which are already in the data) and map lyrics through those anchors. Do not offer Vocals for charts without anchors; fall back to a 'karaoke over preview' or lyric-less hum mode.

### [major] 'Real melody' effectively does not exist
- Where: src/61-lyrics.js:132-157; src/62-parts.js:25-29; src/71-inst.js:69-75; vendor/hooktheory.json.gz (chords only)
- Evidence: Melody is only produced when the player uploads an audio file of the song (Basic Pitch 'highest strong note' during sung lines, which will pick up guitars/keys as readily as the voice; quality on real mixes not measured, test uses a synthetic wav). Without a file the scoring target is any chord tone (62-parts.js:28), i.e. not the tune. The Hooktheory/Sheet Sage source dataset contains transcribed melodies aligned to the audio, but the embedded table kept only chords.
- Fix: Re-export the Hooktheory data with melody notes (scale-degree + rhythm, aligned to clip start) for the 15k songs it covers and use it as the vocal line for those passages; for the curated pack, author melodies as part of the chart. Drop the 'bring your own mp3' step from the main flow.

### [minor] Metre handling loses 830 Hooktheory songs' bar structure and mangles syncopated chords
- Where: src/26-chart.js:182; src/25-lookup.js:472-494; src/20-songs.js:5
- Evidence: 830/15,065 Hooktheory songs have clips in 6/4, 5/4 or 9/4, which are not in TIMES and are laid out as 4/4. 27/61 offline charts contain bars where pushed chords (3.5 + 4.5 beat pairs, e.g. Wonderwall, Let It Be: '. . G .', 'F C/E C .') are rounded to odd beat positions instead of being quantised to the bar.
- Fix: Convert 6/4 -> 6/8 or 2 bars of 3/4, quantise chord starts to half-bars with an 'anticipated' flag (push) rather than moving the chord, and validate that sections are whole bars.

### [minor] Charts are cached per iTunes trackId on one device only
- Where: src/26-chart.js:14-20; src/61-lyrics.js:38-41
- Evidence: Cache key 'it'+trackId, 80 charts max in localStorage; the same song on another album/remaster/device is a fresh lookup (and a fresh paid Claude call on the web path). Lyrics cache likewise per trackId.
- Fix: Key charts by a canonical work id (normalised title+artist, or ISRC/MusicBrainz recording group) in the shared service; clients keep a small local mirror.

## Keep
- The embedded hashed index design (1.8 MB for 457k title|artist keys, 33 ms load, 0.5% false positives) and Lookup.normTitle/artistVariants/titleSlugs normalisation: cheap, fast 'do we have it' checks that already drive the 'in chord data' badge.
- Hooktheory table as evidence: its sounding keys were right on 60 of 61 songs I could judge by ear-knowledge (only Viva la Vida came out as the relative minor), and its chord qualities are accurate transcriptions of the recording. Keep it for key, tempo evidence, chord correction (htMatch/htCorrect) and, once re-exported, melody.
- The 'never invent chords' principle and provenance record (prov: source, row, fit, issues) - keep as internal QA data even if hidden from players.
- Pitch/capo reasoning in Chart.build + Chart.recommend + applyChoices (capo vs transpose vs tune-down, using chordDifficulty): produced the right answer in the mocked runs (Wonderwall capo 2, Riptide capo 1). It should run always, not only on conflicts.
- parseChordSheet (paste a tab): correctly read section headers, capo line, repeats and skipped lyric lines in my test; a good escape hatch and a good ingestion tool for building the curated pack.
- validateSong/compileSong as the single gate for every chart source (bounds, sanitised URLs, section/bar caps).
- Lookup.rankRecordings / isVersion (original studio recording over live/cover/karaoke) - should be applied to the main search too.
- LRC parsing (parseLrc) and the piecewise time-map idea (mapBeat/fileMap); the map format is right, it just needs real anchors.
- Abortable, step-reporting pipeline (AbortController through every fetch, onStep) and specific error copy for API-key/web-search failures.

## Overhaul ideas
- (L) Curated core catalogue shipped in the build: 300-500 most-wanted guitar songs, each hand-verified with full form (named sections in played order, bar-exact chord lengths), felt tempo + metre, sounding key + recommended capo with easy shapes, per-section strum pattern, groove id, difficulty tier, and section start times in recording seconds. Author them with the existing paste parser + Hooktheory evidence, review by ear. — The owner's test songs are the same 200 songs every beginner asks for; today even Wonderwall and Riptide come out as 50-second barre-chord fragments with no strum. A verified pack makes the headline promise true, instant and offline.
- (L) One chart service (the planned worker) as the single online source: canonical work id -> cached chart; on a miss it generates once (LLM with web search for sections/chords, checked against Hooktheory and the preview audio), validates, stores for all players. No personal API key in the player flow. — Removes the 24% dead-end, the bring-your-own-key wall, the dependence on Hugging Face's viewer API/ListenBrainz/Spotify oEmbed from the browser, and per-device re-lookups; makes quality improvable centrally.
- (M) Chart schema v2 with hard validation: sections[{name,type,startSec,bars[{chords[{name,beat}]}],strum,groove}], bpmFelt, metre, keySounding, capo, arrangement tiers (easy/full), anchors for lyrics, confidence. Reject or downgrade anything whose total length is not within about 5% of the recording, whose tempo is outside 55-150 felt bpm without a flag, or whose chords do not start on allowed beat positions. — Every measured failure (fragments, 246 bpm, smeared bars, no strum, lyrics off the end) is something a validator would have caught before the player saw it.
